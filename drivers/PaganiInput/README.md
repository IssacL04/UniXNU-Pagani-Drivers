# PaganiInput

Physical input for the OnePlus 13T PKX110, using the original 21H461 `IOHIDDevice` parser and event dispatch. `pagani-buttons=1` starts the PMIC keys; `pagani-touch=1` starts a separate S3910 device. Its descriptor places a keyboard application before the digitizer, following upstream's hardware-tested generic event-driver matching layout; that device emits only physical touch reports. Stage7Probe starts them after the original HID resources and the GOP display are available. Their failures are reported without failing display startup.

The S3910 path adopts QUP1 S4, configures the board pins, resets the controller, disables HBP raw reports and selects the vendor's on-controller LBP mode. Reads use full-duplex SPI with `0xff` transmit bytes. The first validated header selects TouchComm v1 or v2. V2 checks header CRC6 and payload CRC16, uses ACK/RETRY for continuation, retains the sequence bit when a command is retried, and respects the controller read/write limits. It installs and reads back a bounded report format before accepting contacts. Ten stable contact IDs map to 0..32767 coordinates; finger and glove classifications are accepted, palms are dropped, and removed contacts receive explicit release reports. A transport failure releases held contacts and disables that device until reboot. No controller firmware is uploaded or erased.

The PMIC observer reads PON SID 0 peripheral 0x13 and GPIO SID 1 peripheral 0x8d. On this board PON bit 7 is Power, PON bit 6 is Volume Up, and the active-low GPIO is Volume Down. A 32 ms filter debounces both edges; failed reads release all keys. The driver never writes PMIC peripheral configuration.

Board addresses and wiring are supplied by the device's `PaganiPeripherals.h`. SM8750 clock and SPMI operations come from `Sm8750Platform/PeripheralIO.h`. SPI uses the selected `QcomGeniSpi` component. The main `build-pagani-peripherals.py` qualifies the original 207-slot HID ABI and the compiled subclass; `build-stage7-display.py` includes the late-registered objects in its archive.

Run `python3 <device>/scripts/test-peripherals.py --tree <resolved-tree>` for the portable transport, contact, debounce and MMIO tests. The tests use simulated hardware. The HID descriptor layout follows [NativeHidInput](https://github.com/UniXNU/NativeHidInput/tree/5f3a37c), with its notice retained in `LICENSE.HID`.

`pagani-peripheral-status=1` keeps three diagnostic rows below the camera cutout, refreshed after frame copies and once per second. `KEYS`, `TOUCH` and `PANEL` show the current stage, hexadecimal result `r`, hexadecimal sample `v`, and decimal successful-report/command count `n`. Setup failures retain the failing stage. For keys, `PMIC sample` packs PON in bits 8..15 and GPIO in bits 0..7; for touch, `ATTN wait` shows the pin level, `HID report` shows the active contact-ID mask, and TouchComm failures show `T<version> <command> <stage>`. Version 0 means that no valid protocol header has been identified. For `header` and `continued`, `v` packs the first four received bytes in little-endian order; validation stages retain the rejected length, status or value. `r=0` from HID means the kernel accepted a report; it does not prove that backboardd received it. Disable the overlay after input qualification to uncover the top of the UI.

Build 50 reached the lock screen after skipping Setup. The user confirmed short power-key presses switch the screen off/on and a long press opens the shutdown UI; the key report count also changes for volume presses. Touch stopped at `TouchComm start` with `r=ffffffb9` and no reports. The raw value was hidden by the camera cutout. The full-duplex and protocol changes pass host tests but still need a hardware retest.

Current limits: ATTN is sampled every 8 ms and keys every 16 ms; GIC interrupts and system-sleep wake are not implemented. SPI uses FIFO PIO and retained GENI microcode. Cold regulator enable, GPI DMA, v1 command fragmentation and firmware recovery are not implemented. The firmware must expose LBP and an application identification report. Real contact orientation, report continuity and system edge gestures still need device calibration. Host tests do not establish usable touchscreen input.

The transport was compared with the [OnePlus S3910 HBP implementation](https://github.com/OnePlusOSS/android_kernel_modules_and_devicetree_oneplus_sm8750/tree/6a196f79f77acd55cf302e1696c038e4cad99254/vendor/oplus/kernel/tp/hbp/hbp/chips/synaptics/s3910) and [data-a-live's S3910P path](https://github.com/ShueiTsuki/data-a-live/blob/ba094818ed915cd3689937180a6f619c0e9c86ef/wsl/pandora_touch.c). The latter also identifies v1/v2 and fills reads with `0xff`; its SM8850 GPI, regulator wiring and Xiaomi raw-frame algorithm are board-specific. The local protocol implementation remains independent of the Linux driver. Tests exercise the actual SPI read adapter, fixed v2 command bytes, independent CRC checks, fragmented reads/writes, delayed/retried replies, corrupt packets and bounded raw-frame draining.
